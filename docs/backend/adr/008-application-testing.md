# Выбор стратегии тестирования приложения

* Статус:  Accepted
* Дата: 30.10.2026

## Контекст и Проблема

Проект находится на этапе MVP и необходимо выбрать способ тестирования приложения. Тестирование должно покрывать все
сценарии использования, но не должно затрачиваться много времени на его поддержку, т.к. проект находится на этапе MVP.

## Рассмотренные варианты

* Ручное тестирование
* Написание интеграционных/E2E тестов
* Полное покрытие тестами приложения: unit, integration, E2E.

## Решение

Из-за маленькой кодовой базы и статуса MVP, было принято решение использовать ручное тестирование с
использованием Postman. Написание авто тестов или полное покрытие тестами приложения займет большое количество времени
что является недопустимым в данный момент развития проекта. В дальнейшем будет реализованно полное покрытие тестами.

## Последствия

* **Плюсы:**
    * Будет гарантированна работа всех сценариев использования приложения
    * Небольшие временные затраты на поддержание/проведение тестов
    * Небольшие временные затраты на написание тестов
* **Минусы / Риски:**
    * Риск наличия специфичных ошибок, которые проявятся в дальнейшем или в ситуациях, которые не были протестированы 
    * Наличие ошибок после рефакторинга или дальнейшего развития проекта, которые могут быть выявлены только позже
    * Невозможность автоматизации тестирования в рамках CI/CD
