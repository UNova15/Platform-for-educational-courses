# Выбор базы данных

* Статус: Accepted
* Дата: 01.03.2026

## Контекст и Проблема

Согласно описанию в [NFR](../NFR.md) в проекте требуется соблюдение строгой консистентности для всех операций записи а
также быстрое выполнение операций чтения. В дальнейшем возможно выполнение финансовых операций (покупка курсов). Также
требуется хранение файлов и видео как контента уроков. База данных должна обладать отказоустойчивостью и давать
возможность соблюдения строгой консистентности. Также база данных должна быть масштабируемой под описанные в NFR
нагрузки. При этом основной объем данных (до 10 ТБ/год файлов и видео) будет делегирован в S3, что снимет проблему
нехватки дискового пространства с реляционной БД.

## Рассмотренные варианты

### Реляционные базы данных:

* PostgreSQL
* MySQL

### Не реляционные базы данных:

* MongoDB
* S3 (MiniO)

## Решение

Было решено использовать PostgresQL и MiniO как S3 хранилище. PostgresQL позволит обеспечить строгую согласованность
данных что очень критично в данном проекте, позволяет выполнять атомарные операции (транзакции), а файловые данные будут
хранится в MiniO. PostgresQL является популярной и активно развивающейся базой и у разработчика есть опыт работы в ней.
Она позволяет выполнять быстрые read операции при использовании индексов. Структура основных сущностей доменной области
хорошо ложится на реляционную модель данных в виду жесткой определенной структуры и жестких связей между сущностями. В
дальнейшем возможно использование MongoDB для сущностей с динамической структурой (Например сущность урок при расширении
полей в нем).

## Последствия

* **Плюсы:**
    * Возможность обеспечения строгой согласованности данных
    * Хорошая отказоустойчивость и надежность базы
    * Возможность выполнения быстрых read операций
* **Минусы / Риски:**
    * Сложность горизонтального масштабирования на запись по сравнению с NoSQL решениями. Однако горизонтальное
      масштабирование на чтение легко решается Read-репликами
