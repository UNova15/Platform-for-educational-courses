# Выбор фреймворка

* Статус: Accepted
* Дата: 01.03.2026

## Контекст и Проблема

Т.к. данный проект будет иметь множество интеграций внутри себя что описано в [общем описании](../../README.md)
фреймворк должен позволять достаточно легко подключать к себе сторонние интеграции, и быть достаточно популярным для
дальнейшего поиска сотрудников для расширения проекта и быстрым для обеспечения требуемой
[производительности](../NFR.md)

## Рассмотренные варианты

* Spring
* Micronaut
* Quarkus

## Решение

Был выбран вариант Spring и использование следующего стека из платформы Spring:

* Spring Boot для обеспечения базовых функций Spring, и возможности легкой автоконфигурации за счет механизма стартеров.
  Также добавляет поддержку AOP и Событий, которые будут часто использоваться в проекте
* Spring Security для обеспечения безопасности приложения
* Spring data Jdbc как ORM фреймворк для соблюдения строгих границ агрегатов и очевидного прямолинейного поведения. Для
  Query запросов используется Spring jdbc client. В будущем возможен переход на Spring data JPA как основной ORM
  фреймворк и JOOQ для типобезопасных Query запросов и динамической генерации запросов
* Spring web mvc для создания веб API

## Последствия

* **Плюсы:**
    * Самый популярный и известный Java backend фреймворк. Большой рынок труда и большая поддержка фреймворка.
    * Большой количество готовых интеграций и большая экосистема
    * Достаточно быстрый
* **Минусы / Риски:**
    * Достаточно старый, внутри много легаси кода
    * Основа работы - рефлексия. Будут трудности если необходимо будет использовать AOT для оптимизации
      старта/потребления памяти
