# Выбор языка программирования

* Статус:  Accepted
* Дата: 01.03.2026

## Контекст и Проблема

В соответствии с требованиями к производительности и отказоустойчивости, описанными
в [Производительность](../NFR.md) основная нагрузка будет идти на Read операции. Согласно
функциональным требованиям не предвидятся задачи направленные на высокую нагрузку CPU. В случае появления таких задач их
выполнение можно вынести в отдельные сервисы с отличным от данного стеком.

## Рассмотренные варианты

* Java/Kotlin
* Go
* Python
* C#

## Решение

В качестве языка программирования для данной системы была выбрана Java с последующим возможным переходом на Kotlin.
Данный язык обладает нужной производительностью, большой экосистемой и имеется большое количество разработчиков на рынке
что ускорит процесс поиска сотрудников для дальнейшего развития проекта, данный язык лучше всего знает основной
разработчик Бекенд части, что сделает процесс разработки более быстрым.

## Последствия

* **Плюсы:**
    * Высокая производительность
    * Большая экосистема
    * Большой рынок труда
    * Строгая типизация, удобная интеграция библиотек/фреймворков

* **Минусы / Риски:**
    * Возможно большое потребление оперативной памяти из-за архитектуры языка (Потребление может сократится при введении
      Project Valhalla).
    * Более сложная настройка внутренних механизмов(например AOT), требуется больше знаний и навыков (В результате
      настройки можно сократить потребление памяти и время старта)
